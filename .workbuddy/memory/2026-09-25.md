## 三个 BUG 修复（用户报告：office 编辑报错/扩展名、阅读态高度、H5 分享弹登录）
复现环境：repro-office.sh（起 18310 服务 + fixture 库 + curl 上传建文档 + playwright 无头 Chrome）。

### BUG 1 根因（最重要）：OnlyOffice 自动保存从未生效
- 实测：单元格输入 → OnlyOffice 底栏显示「所有更改已保存」，但**落库 content 不变**；
  只有手动点「保存」按钮才落库。等于改动随时可能丢。
- 根因：`OnlyOfficeEditor` 挂载时立即 `manager.getEditor().subscribe(...)`，此刻 iframe 内
  `Asc.editor` 往往未就绪 → subscribe 抛「OnlyOffice SDK API is not ready」→ 被原有 try/catch
  **静默吞掉且不重试** → `asc_onDocumentModifiedChanged` 永远没人听。
- 修复：订阅失败按 1s 间隔重试（最多 60 次），成功后正常防抖保存。
- 验证：编辑后 content 更新（新 CAS url，filename/ext 保持不变），0 控制台错误。
- 探针结论（可复用）：自托管 SDK（非 CDN 模式）下事件走 `iframe.contentWindow.Asc.editor.asc_registerCallback`，
  `asc_onDocumentModifiedChanged` 回传 `(true/false)`；探针法 = 在 page.evaluate 里给 iframe 注册回调。

### BUG 2：阅读态 OnlyOffice 高度恒 556px（不随窗口伸缩）
- 根因：阅读分支没有给高度链，编辑器根 div 靠 minHeight:600 兜底（600-44 工具条=556）。
- 修复：BookPage 阅读分支对 api + sheet/word/ppt 走「标题固定 + 正文 height:100% 弹性列」；
  DocContent 的 fillHeight 扩到 office 类型并改为 flex 列（body 包 flex:1 minHeight:0）；
  DocSharePage 同样处理（isApi → fillViewport = api || office）。
- 验证：win 700/900/1200 → 容器 556（minHeight 兜底）/608/908，随窗口变。

## 第四类 BUG 修复：编辑/阅读来回切换 → 幽灵 Word 编辑器 + 扩展名错乱
用户报告：刚建的表格 / 导入的 xlsx / pptx，编辑↔阅读来回切几次就报错，被误判成 Word 格式，阅读态有时能识别有时不能。

### 根因（OnlyOffice 单例并发竞态）
- `EditorManager` 是**单例**（按 containerId `iframe-office-id` 取），而 React 在同一提交内会**两个实例并发 mount**（两个 effect 都调 `create()`）。
- 交错过程：create#1 `open(xlsx)` 让出 → create#2 `open(xlsx)` 挂出**正确的 xlsx 编辑器** → 此刻 create#1 的宿主**卸载（cancelled）**→ `destroy()` 把单例 `server.reset()`（id="", fileType="docx"）→ create#1 的 `open` await 恢复 → `mountDocEditor()` 里 `server.getDocument()` 发现 id="" → **惰性 `openNew()` 无参兜底 → "New Document.docx" 空 Word 编辑器顶掉正确编辑器**。
- 之后自动保存把 `filename="New Document.docx"` 的引用写进正文（字节仍是 xlsx）→ 下次打开 OnlyOffice 按扩展名选错编辑器 → 报错「内容与扩展名不一致：docx」。
- 复现手法：无头 Chrome 打开编辑态，注入 MutationObserver + 给 `EditorManager.server.open/openNew/reset`、`mountDocEditor` 打补丁记录调用序列，切换一轮即看到 xlsx 挂载后 10ms 内被 docx iframe 顶掉。

### 修复（库层 epoch 守卫 + 业务层双保险）
- `editor-manager.ts`：
  - `destroy()` 在 `server.reset()` **之前** `this.destroyEpoch++`；
  - `create()` 在自身初始 `destroy()` 之后取样 `epoch`，在 `await server.open` 后（L1672）与 `mountDocEditor` 前（L1703）两处 `if (this.destroyEpoch !== epoch) return` —— 残留在途的 create 即便恢复也**绝不挂载**，杜绝幽灵编辑器。
- `onlyoffice-manager.ts` `openDocument`：`this.ready = this.editor.exists()`（被中止的 create 报告 `isReady()===false` 而非假就绪）。
- `OnlyOfficeEditor.tsx` 双保险：
  - 打开时 `healName` 强制文件名扩展名=docType（引用里历史脏数据也不怕）；
  - 保存时 `fileName` 与 `officeRefFromUpload` 一律用 `extForDocType(docType)`；
  - `mount()` 至多重试 3 次，若 `!manager.isReady()` 抛「编辑器被频繁切换打断，请重新进入编辑模式」（绝不把空实例当正常编辑器用）。
- `tsc --noEmit` rc=0；已重建嵌入二进制。
