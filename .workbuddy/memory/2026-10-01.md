## docker compose 构建报 `docker/dockerfile:1` 拉不动（国内网络）

### 根因
`Dockerfile` 第一行 `# syntax=docker/dockerfile:1` 指定 BuildKit 的 Dockerfile 前端镜像，
这个镜像由 **buildkitd 自己联网**去 Docker Hub 拉，既不吃 `docker pull` 的镜像加速，
也不吃 dockerd 的代理配置。直连超时即报
`failed to resolve source metadata for docker.io/docker/dockerfile:1 ... i/o timeout`。
**与项目代码 / Dockerfile 语法无关**。

### 三处配置的管辖范围（最容易配错的地方，记牢）
| 配置位置 | 实际管什么 | 对 syntax 前端有效 |
| --- | --- | --- |
| `~/.docker/config.json` 的 `proxies` | `docker buildx build` / `docker compose build` 的网络（含 syntax 前端） | ✅ **唯一有效** |
| `/etc/docker/daemon.json` 的 `registry-mirrors` | `docker pull` 拉基础镜像（alpine/node/golang） | ❌ 仅加速；`docker/dockerfile` 是否在镜像站同步不保证 |
| `/etc/docker/daemon.json` 的 `proxies` | 仅 `dockerd` 自己 pull | ❌ 对 buildkit 无效 |

- `~/.docker/config.json` 改完**不用重启 docker**，下次 build 即生效（buildkit 每次读用户配置）。
- Docker Desktop（mac/Win）buildkit 跑在 VM 里，`127.0.0.1:7890` 是宿主端口、VM 访问不到 →
  改用 `host.docker.internal:7890` 或走 Desktop 的 `Settings → Resources → Proxies`。
  Linux 上 buildkit 与 dockerd 同机，127.0.0.1 写法直接可用。
- 兜底：`DOCKER_BUILDKIT=0 docker compose build`（classic builder 不拉 syntax 前端；
  本项目 Dockerfile 没用 buildkit 专属语法，能过）；或先 `docker pull docker/dockerfile:1` 预热让 buildkit 复用。

### 写脚本踩的坑（复用时注意）
- `local` 不能写在函数体外的顶层（脚本解析期就报 `can only be used in a function`）。
- `set -u` 下空数组 `"${ARR[@]}"` 在 bash 4.3 及以下会炸，写成 `${ARR[@]+"${ARR[@]}"}`。
- dry-run 分支里要引用 ARGS，数组必须在 dry-run 判断**之前**组装。
- 把 docker / docker compose 可用性检查放到真正执行前，`--help` 与 `--dry-run` 才能在没装 docker 的机器上跑。

## OnlyOffice 1.1G 资源：已从工作区与全部 git 历史移除（2026-10-01 ~03:15）
- **教训前提要核实**：我一度把它当成「并行会话的未跟踪产物」，实查才发现它被 `git add -A` 扫进了今天 00:46 的
  `f377ac40`（v1-mm 的 HEAD），`git ls-files web/public/packages | wc -l` = 19629。
  `git status` 看不见是因为**已跟踪且无改动**，不是因为被 ignore（`git check-ignore` 返回 exit 1）。
  → 判断某堆文件「是否已入库」必须跑 `git ls-files <path> | wc -l`，不能凭 status 推断。
- **只在一个提交里 + 该提交就是 HEAD ⇒ 不必 filter-repo**：`git log --all --oneline -- <path>` 只有 1 条时，
  `git rm -r --cached <path>` + `git commit --amend --no-edit` 即可达到同样的全历史清洗效果，
  不会去重写其余上百个提交的对象。`v1-mm` 无 upstream，改历史不需要 force push。
- **amend 不会捎带未暂存改动**（Dockerfile/README/本次思维导图成果都安全），前提是 stage 里只有那批删除。
- gc 前 `.git` 499M → `git reflog expire --expire=now --all && git gc --prune=now --aggressive` 后 **47M**。
- 实测收益：`.git` 503M→47M、`web/dist` 1.3G→109M、embed 二进制 997MB→**137MB**（build-embed.sh 重建）。
- 稳妥做法（下次照抄）：先整仓备份（含 .git）到 tmp → 核实源码零引用 + 其他会话改动不依赖 →
  宿主批量删除守卫用「find -type f -delete 再 -depth -type d -empty -delete」两步法 → git rm --cached → amend → gc。
