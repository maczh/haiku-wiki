## 块手柄悬停不显示：真根因（无头 Chrome 实测，推翻此前所有推理修复）

用户多次反馈「悬停依然不显示块手柄」，此前基于推理的 resolveBlock 修复全部落空。本次搭最小诊断页

### 真根因（与此前推理完全不同）
1. **Vditor 为所有模式各建一个 `.vditor-reset`**（wysiwyg/sv/ir/preview 共 4 个，实测），只有 `.vditor-ir` 下的那个
   是正文，其余是空壳（children=0, size 0×0）。裸 `host.querySelector('.vditor-reset')` 命中 wysiwyg 空壳 →
   `reset.contains(el)` 恒 false → resolveBlock 恒 null → 悬停永远不显示。**这是「悬停丢失」的真正根因。**
2. **`data-block` 是静态占位 "0"**（dist 源码与实测双重确认），不是行号；`querySelector('[data-block="N"]')`
   与 `Number(getAttribute('data-block'))` 都恒等于 0/第一个块。FormatToolbar 的 findBlock 正是这么写的——
   这才是「菜单操作全打第一行」的真根因（此前归因于行号映射是错的）。
3. 顶层块是 `.vditor-reset`（一个 `<pre>`）的直接子元素：标题/正文是 `<p>`（标题带 `.vditor-ir__marker--heading`），
   代码块等包在 `.vditor-ir__node` 里；都带 `data-block="0"`，文档序索引 = 源行锚点（近似）。
