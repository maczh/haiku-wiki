## 本轮需求（一次性三项新增功能）

1. **DWG**：导入 `.dwg` → 后端存原件 + 自动转 `.svg`/`.png` → 前端预览可缩放、可上下左右拖动 → 可导出 `.dwg`/`.svg`/`.png`。

## 落地实现

### 关于「导出 .vsdx」（需求原文要求的一项）——已查实为组件能力缺失，非实现偷懒

自托管的那份 draw.io 组件里与 vsdx 相关的代码只有**读**能力，**没有写**能力，三处硬证据：

| 证据 | 位置 |
| --- | --- |
| `EditorUi.prototype.vsdxExportEnabled=function(){return "atlassian"==this.getServiceName()}`，而 `getServiceName(){return "draw.io"}` | `drawio/js/app.min.js` |
| 导出菜单项 `exportVsdx` 的加入条件是 `!g.vsdxExportEnabled() \|\| "undefined"===typeof VsdxExport && g.isOffline() \|\| this.addMenuItems(...)` → 开源版恒不加入 | 同上 |
| `VsdxExport` 只出现在 `app.min.js` 的**调用处**（`new VsdxExport(this).exportCurrentDiagrams(c)`），**全包无该类定义**；`extensions.min.js` 里只有 `mxgraph.io.vsdx.*`（`vsdxModel`/`vertexShapeMap`/`mxVsdxConstants`，即导入解析器） | 全目录 grep 验证 |

即：vsdx 导出是 **Atlassian 版专属**（服务名硬门禁）且实现未随开源包发布。
因此前端与 README 都把 `.vsdx` 标注为**仅支持导入**；`.drawio`/`.svg`/`.png` 三种导出正常。
若将来确需 vsdx 导出，只能服务端自研 mxGraphModel → VSDX(OOXML/zip) 写出器，属独立工程。

**界面文案已按上述事实改写**（原来写的是「官方未定义其导出协议」，不准确）：
`DrawioEditor.tsx` 说明条改为「`.vsdx` 导出是 draw.io 企业版（Atlassian）专属能力，开源版未随包提供导出实现，
故菜单中无此项；如需 Visio 文件，请在 Visio 或转换工具中另存。」，`lib/drawio.ts`、`README.md` 同步。
重新构建后生产形态实测确认：说明条含「企业版（Atlassian）」「未随包提供导出实现」、旧说法已无、
导出菜单仍为 3 项（`.drawio`/`.svg`/`.png`）、`/drawio/` 静态路径回归 200。

## 本轮修掉的缺陷（都是浏览器实测/生产形态复验抓出来的）

0. **无文件头 BMP 的降级预览分支实际不可达（后端）**：`extractEmbeddedPreview` 是靠搜 `"BM"` 魔数找 BMP 的，
   而「只有 `BITMAPINFOHEADER`、没有 `BM` 两字节」的无文件头形态里没有这个魔数 ——
   于是 `decodeHeaderlessBMP` 永远走不到，**凡是只存 BITMAPINFOHEADER 的图纸都会被判成「文件内不含预览图」**，
   把本来有救的文件判死（而这条兜底路径正是「没装转换器」时的唯一希望）。
   修：新增按 `BITMAPINFOHEADER` 字段（`biSize`∈{40,108,124}、`planes==1`、合法 bpp、`compression<=3`、
   宽高 8–20000）的受控扫描，解码成功才采用。
   新增 `internal/service/exportx/cad_degraded_test.go`（5 个用例）用**合成 DWG** 锁住整条降级链路：
   内嵌 PNG / 无文件头 BMP / 服务层契约 / 无转换器无预览图时的诚实报错 / 假魔数不被误判。
   注意：真实夹具（libredwg test-data）都是工具转出来的、**不带内嵌缩略图**，只能覆盖矢量路径 ——
   降级路径必须靠合成夹具，这也是这个缺陷此前没被发现的原因。

1. **draw.io 资源探测误判（前端）**：`drawioAssetsReady()` 原用 `Range: bytes=0-64` 探测，
   而 `drawio/index.html` 前 65 字节是 `<!DOCTYPE html><html><head><title>Flowchart Maker…`，
   指纹串落在窗口外 → 严格实现 Range 的服务器（Vite dev）上被判「组件未部署」。
   改：去掉 Range、整取后校验前 4KB，指纹正则扩为 `drawio|mxgraph|geInfo|bootstrap\.js`。
2. **容器字体路径错误（后端）**：`Dockerfile` 的 `EXPORT_FONT_PATH` 指向不存在的 `wqy-microhei` 路径
   （apk 的 `font-wqy-zenhei` 实际装在 `/usr/share/fonts/wqy-zenhei/`）；且 `resolveFont()` 对
   显式指定字体**硬失败**，一旦路径不对会让所有 PDF/PNG 导出全线报错。改为补 Alpine 真实路径 +
   「指定字体不可用时告警后回退自动探测」。
3. **`/drawio/` 被 SPA 兜底吞掉（后端，生产形态致命）**：路由 `NoRoute` 用
   `fs.Stat(distFS, strings.TrimPrefix(path,"/"))` 判断静态资源是否存在，但 **`fs.ValidPath` 不接受尾随斜杠**，
   `fs.Stat(fsys,"drawio/")` 返回的是 `invalid argument` 而不是「不存在」→ `/drawio/` 被误判为非静态资源，
   回退成应用自身的 `index.html`（621 字节）。表现：**embed 生产形态下内嵌 draw.io 的 iframe 拿到的是寄海文库的 HTML，
   绘图功能整个失效**（Vite dev 由自己的静态中间件服务，不复现 → 只在生产形态复验时才暴露）。
   修：抽出 `staticProbePath()`，目录型请求补 `index.html` 再判断存在性；新增
   `internal/router/static_spa_test.go` 三个用例锁住不变量（归一化后必须能被 `fs.Stat` 接受 + SPA 兜底不能失效）。

## 环境要点（本轮新踩）

- Go 有**两份**：托管 `go1.23.4`（`/home/macro/.workbuddy/binaries/go/bin/go`，GOROOT 自包含）与
  系统 `go1.25.7`（`/usr/local/go/bin/go`）；项目 `go.mod` 要求 `go 1.22`，两者都能构建。
  （此前一度以为托管路径不存在，是误判。）
- 真正会踩的是**工具调用的 shell 里 `HOME` 可能为空**：此时 `go` 报
  `module cache not found: neither GOMODCACHE nor GOPATH is set`，**且退出码仍为 0**，
  看起来像成功（`go build ./...` 便是在这个状态下「静默什么都没做」）。
  必须显式 `export HOME=/home/macro` + `GOPATH`/`GOMODCACHE`/`GOCACHE`。
- `/tmp` 是 10MB tmpfs → `TMPDIR` 必须改到家目录；Go 编译/集成测试会 `no space left on device`。
- libredwg 顶层 Makefile **没有** `dwg2dxf` 目标 → 必须 `make -C src` 之后再 `make -C programs dwg2dxf dwgread`。
- agent-browser 的 ref 与页面状态**不跨 Bash 调用保留** → 所有浏览器步骤必须封在同一个脚本里；
  上传隐藏 `input[type=file]` 只能靠页面内 `File`+`DataTransfer`+`change` 事件。
- **后台服务进程**：`ps` / `/proc/*/cmdline` 在本沙箱都看不到它们（在另一个 PID 命名空间），
  但**用 TaskStop 回收本会话启动的后台任务是可以的**（实测成功回收 8080 的 `go run` 实例）；
  只有来自其它会话的进程才真正无法处理。判断服务是否存活一律用 `curl` 探活。

## 接口文档导入：支持 Apifox「项目」导出格式（含 $ref 解析）

- 问题：Postman 导入正常，Apifox 导入失败（无法识别）。用户给了真实文件 `寄海海鲜火锅小程序点餐模块.apifox.json`（Documents 下）。
- 根因：`importApiSpec` 只识别 Swagger2/OpenAPI3/Postman，对 Apifox「项目」导出格式（顶层 `apifoxProject` 标记 / `$schema.app==='apifox'`）直接返回 null。
- Apifox「项目」格式结构：
  - `apiCollection[]` 是文件夹树（folder 有 `items`，api 叶子有 `api` 字段）；`api` 内含 `method/path/parameters{path,query,cookie,header}/requestBody{type,jsonSchema.$ref}/responses[].jsonSchema.$ref/description/tags`。
  - **schema 定义不在顶层 `definitions`**：藏在 `schemaCollection[0].items[]`，每个 item 的 `id` 是完整的 `#/definitions/<id>` 字符串（51 个，正好对应 51 个引用），真实 schema 在 `item.schema.jsonSchema`。
