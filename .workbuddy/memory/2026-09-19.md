### 关键技术决策与坑
- **组件选型**：`vxe-gantt` 是 Vue 3 专用，无法用于 React18 → 改用 **SVAR React Gantt**
  (`@svar-ui/react-gantt@2.7.3` + `@svar-ui/gantt-locales@2.7.2`)，MIT。
- **致命 bug（已修）**：`ganttToSvar` 不能给所有任务写 `open:true` —— SVAR `lib-state` 的 `parse()` 把每个任务
  `data` 置 `null`，`toArray()` 遇 `open===true && data===null` 抛 `Cannot read properties of null (reading 'forEach')`
  → 整图白屏。**只给有子任务的父节点写 `open:true`**（用 `hasChild` 集合判定）。
- **getTask 键类型坑（已修）**：SVAR `byId` 是 `Map`，键为**数字** id；DOM `data-id` 是**字符串**，
  悬停气泡/编辑器里拿字符串调 `getTask` 永远查不到。统一抽 `resolveSvarTask(api, id)`：先 `getTask(Number(id))`，
  失败再遍历 `serialize({data:'tasks'})` 按 `String(t.id)===String(id)` 兜底。
- **外框被 hover 覆盖（已修）**：SVAR 的 hover 规则用 CSS-Modules 哈希类，与注入选择器同特异度但加载更晚 →
  覆盖我们的 `box-shadow`。修复：选择器加深为 `.hk-gantt .wx-bar[data-id="X"]` 并对 `box-shadow` 加 `!important`。
- **零 CDN**：只能用 `@svar-ui/react-gantt/style.css`（无 url()），不能用 `all.css`（含 `@font-face` 指向 cdn.svar.dev）。
  `wxi-*` 图标字体缺失 → 本地 CSS 字符字形兜底。
- **阅读态只改进度**：`api.intercept` 拦掉 `drag-task`/`add-task`/delete/copy/move/indent/split/`*-link`，
  `update-task` 白名单仅放行 `Object.keys(ev.task).every(k=>k==='progress')`。进度手柄派 `update-task {task:{progress}}`，不走 `drag-task`（源码逆向确认）。
- **按需加载**：甘特代码在独立 chunk（`GanttChart-*.js` ≈265KB / `GanttChart-*.css` ≈35KB），入口 `index-*.js`
  中 `wx-gantt/svar/GanttChart/vxe` 计数必须为 0（已通过）。
- **状态灯/优先级前后端规则同步**：`web/src/lib/gantt.ts` 与 `server/internal/service/exportx/gantt.go`
  各实现一份，判定顺序一致（已结束→已超期→未开始→进度拖延→正常）。

## v6（12:xx）悬停气泡只有部分任务能弹——根因与修法
- **现象**：只有最顶部第一个任务进度条悬停弹气泡，其余不弹（用户本轮反馈）。
- **根因（探针铁证）**：SVAR 时间轴里部分任务 bar 中心坐标 `elementFromPoint` 命中的真实顶层元素是 `.hk-gantt` 的**父级 flex DIV**（祖先），不是 `.wx-bar` 子节点。原悬停用 React `onMouseMove`（**冒泡监听在 wrapper**），真实顶层元素在 wrapper 祖先之上时事件只向上冒泡、**到不了 wrapper 监听器** → 该任务不弹。任务 1/2 顶层元素恰在 bar 内 `.wx-content` 上故正常。
- **修法（GanttChart.tsx）**：① 监听改 `document` **捕获阶段** `addEventListener('mousemove', onMove, true)`（从 document 向下派发，无论光标正下方是谁都触发，脱离冒泡假设）；② 命中测试改**遍历 `.wx-bar` 矩形包容**（`getBoundingClientRect` 内即命中），脱离 `e.target.closest('.wx-bar')`；③ `tipBarRef` 同条只跟光标、跨条才重算；④ `rootRef`/`wrapRef` + 卸载清理。
- **验证假阳性陷阱**：旧 `gantt-edit-hover.sh` 用 `bar.dispatchEvent(mousemove)`（target 恒为 bar）假阳性漏掉回归 → 已改为向 `elementFromPoint` 真实顶层元素派发；现 **3/3** 真绿。
- **验证**：真实悬停探针 任务A30%/B40%/C0%（任务3 此前卡 B 已修正）；强化 edit-hover 3-3；v3 37-37；api 21-21。本地已提交 `8f3eeb5`，验证报告 `gantt-hover-fix.md`。
- **通用教训（悬停类必记）**：SVAR 甘特 bar 之上常盖透明祖先容器，绝不能用 `e.target` 是否 bar 子节点判悬停；真实悬停测试必须派发到 `elementFromPoint` 顶层元素。

## v8（12:5x）折叠隐藏后左表格丢行 —— 根因与修法
- **现象**：用户反馈「右边时间轴面板折叠隐藏后，左边表格任务内容减少了」（截图只剩 2 行，未折叠 8 行）。
- **根因（探针铁证）**：左表格**不自己虚拟化**，行来自右侧时间轴的可见区切片（`react-gantt` 内 `tasks.slice(area.start, area.end)`，`area` 由时间轴测量）。v7 用 `display:none` 藏时间轴 → 测量归零 → 只剩 2 行。实测 12 行 → 2 行；改成 `flex:0 0 0;width:0;overflow:hidden`（保持占位）则仍 12 行。
- **修法**：折叠改走 SVAR 原生 `displayMode`（`all|grid|chart`）+ `api.exec('set-display-mode',{mode})`，`init` 内 `api.on('set-display-mode')` 回读同步（SVAR resizer 自带箭头也派发同一 action）。库内宽度规则：`zt(columns,displayMode,gridWidth)` → `all`=`<gridWidth>px`、`grid`=`calc(100% - 4px)`（表格铺满、时间轴压到 0 宽）、`chart`= 0（编辑态退回 add-task 列宽 37px → 我们 CSS 用 `flex:0 0 0!important` 收掉）。
- **顺带修既有缺陷（同样只在实测暴露）**：Willow 渲染的两层 `<div class="wx-theme wx-willow-theme">` 在 SVAR 全部 CSS 里**没有任何规则** → 高度链断在这里，`.wx-gantt{height:100%;overflow-y:auto}` 的 100% 退化为 auto。实测 30 行时 `.wx-gantt` 被撑到 1092px 塞进 718px 容器（`scrollHeight==clientHeight`）→ 下侧行既看不到也滚不到。补 `.hk-gantt .wx-theme{height:100%;min-height:0}` 后 = 718/1092/auto，滚动条回到 `.wx-gantt`（折叠右侧后仍可纵向滚动）。
- **验证**：`gantt-fold-check.sh` 升到 v8 → **30/30**（右侧折叠后表格 23→23 行、时间轴 845→0 宽且 `display:flex`、表格 440→1286、折叠态 scrollTop 136/136 且首行变化、展开后逐像素还原 441/4/845、控制台 0 错误）；v3 37/37、api 21/21、edit-hover 3/3 全绿。几何探针 `gantt-layout-probe.sh`：chart 模式 = 表格 [285..285] w=0 / resizer 4 / content [289..1575] w=1286。
- **通用教训**：① SVAR 甘特左表格与右时间轴**共享可见区**，任何一侧都不能 `display:none`，必须用 `displayMode`；② `.wx-theme` 高度链必须由使用方补，缺了会静默退化为 auto（只在塞进固定高度容器后才暴露）；③ 断言要用「折叠前后相等」的相对不变量，别写死行数（虚拟化渲染窗口随滚动位置变化：滚到底时 23→20 行是正常的）。
