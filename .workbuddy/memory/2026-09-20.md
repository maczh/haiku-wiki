## Docker SQLite 启动失败修复（commit 9e70eca）
- 现象：容器启动报 `failed to initialize database, got error unable to open database file: out of memory (14)`。
- 根因：镜像以 haiku(UID 10001) 运行；宿主机 bind mount 目录 `/root/haiku/data` 属主 root:root 755。SQLite(WAL) 需在**目录**里创建 `haiku.db-wal/-shm`，目录不可写 → SQLITE_CANTOPEN(14)，glebarez 纯 Go 驱动误报为 "out of memory"（与内存无关）。db 文件本身 -rw-r--r-- 属 10001 可写，迷惑性来源即此。
- 修复两层：① `repository.Connect` sqlite 分支打开前用探针文件 `ensureDirWritable` 预检数据目录，不可写时报「数据目录不可写 + chown -R 10001:10001 建议」（database_test.go 两个用例锁行为，root 下跳过只读用例）；② 新增 `docker-entrypoint.sh`（postgres 镜像同款模式）：root 启动 → `chown -R haiku:haiku /app/data /app/conf` → su-exec 降权运行；`--user` 非 root 启动直接透传。Dockerfile 装 su-exec、移除 `USER haiku`、ENTRYPOINT 换入口脚本。
- 注意：`su-exec` 同时加进 fallback apk 分支；镜像内 healthcheck 用的 busybox wget 不受影响。

### 实测发现的线上真实缺陷（已记录进 README「已知限制」，未改代码）
- **`GET /api/search` 在线上（MySQL）恒返回 500 `{"code":50000}`**，任意关键词、带/不带 token 都失败；同一二进制在本地 SQLite 下搜索正常（命中 5 条）→ 确认是方言问题。
- 根因：`server/internal/repository/search_repo.go` 写的是 Go 字符串 `"LIKE ? ESCAPE '\\'"`，Go 已把 `\\` 还原为单个反斜杠，落到 SQL 就是 `ESCAPE '\'`。SQLite 字符串字面量不认反斜杠转义 → `'\'` 是合法单字符常量；MySQL 会把 `\'` 当作被转义的单引号 → 字符串不闭合、语法错误。
- 建议修法（方言无关）：`escapeLike` 改为转义 `!`（`!`→`!!`、`%`→`!%`、`_`→`!_`），SQL 改 `ESCAPE '!'`。
